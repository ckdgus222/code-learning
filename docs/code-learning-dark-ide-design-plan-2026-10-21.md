## 1 목적과 사용자 결정

지금 화면은 안내문이 내용보다 많고, 모든 버튼이 같은 무게로 보여 무엇을 먼저 봐야 하는지 드러나지 않는다. **기능·문구·동작은 그대로 두고 생김새를 시안 B로 바꾼다.**

사용자 결정(2026-10-21):

- 시안 A·B·C 중 B(어두운 IDE형)를 고름.
- 시안에 있던 새 기능 네 가지를 모두 넣음: 코드 줄 옆 단계 번호, 동의 문구 접기, 아래쪽 상태 줄, ⌘P 이동 창.
- 밝은 화면은 두지 않고 어두운 화면 하나만 둠(사용자가 선택지에서 고름).

## 2 바꾸지 않는 것

- **앱 동작 코드는 renderer만 고친다.** `src/main`·`src/preload`·`src/shared`(계약 타입)·`src/core`(분석·AI 실행)·`src/workers`는 그대로다. 그 밖에 고쳐도 되는 것은 맨 위 ‘범위’에 적은 시험·문서·의존성 파일뿐이다.
- **버튼·제목·안내 문구의 글자와 접근 가능한 이름을 유지한다.** 화면 검사가 이 이름으로 요소를 찾는다(예: ‘프로젝트 폴더 열기’ 33곳, ‘한눈에 보기’ 19곳, `evidence-range` 38곳). 예외는 아래 4장(동의 문구)과 3.6(배지 위치)뿐이다. 아이콘만 보이게 바꾸는 버튼은 지금 글자를 `aria-label`로 그대로 둔다(예: ‘찾기 ⌘F’, ‘패널 접기’).
- **경고는 지금처럼 화면 위 알림으로 둔다.** 오류, 변경 감지 제한, 코드 변경·잠자기 복귀, 다시 확인 필요 알림을 상태 줄로 옮기거나 줄이지 않는다.
- **각 보기의 내용 구조는 유지한다.** 흐름 카드, 프로젝트 지도, 변경 보기, 한눈에 보기 카드, 질문 패널의 순서와 정보는 그대로이고 색·간격·테두리·버튼 모양만 바꾼다. 시안의 흐름 화면(단계 목록이 왼쪽 칸에 있고 코드가 크게 보이는 배치)으로 흐름 보기를 다시 짜지 않는다.
- 웹 글꼴·이미지를 쓰지 않는다(`index.html` CSP: `img-src 'none'`, 웹 글꼴 없음). 글꼴은 지금의 시스템 글꼴이고, 아이콘은 인라인 SVG다.
- 새 상태 저장(설정 기억 등)을 넣지 않는다.

## 3 1단계: 어두운 테마와 배치 (커밋 1)

### 3.1 색

`styles.css`의 `:root` 토큰을 아래로 바꾸고 `color-scheme: dark`를 둔다(스크롤바·입력 칸·체크박스가 어둡게 그려지게). 다른 곳에 직접 적힌 색(현재 `#c8d5f5`, `#cfdcfa`, `#fde2e1`, `#8a1f17` 등)도 토큰으로 바꾼다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--bg` | `#14161A` | 상단 줄, 상태 줄 |
| `--rail` | `#181B20` | 왼쪽 아이콘 레일 |
| `--side` | `#1B1E24` | 파일 칸, 오른쪽 패널 |
| `--surface` | `#1F2228` | 가운데 영역, 코드 |
| `--raised` | `#23272E` | 카드, 질문 말풍선 |
| `--line` | `#2C3038` | 테두리, 구분선 |
| `--ink` / `--muted` / `--dim` | `#E6E8EB` / `#A0A8B3` / `#8A929D` | 본문 / 보조 글자·코드 주석 / 줄 번호 |
| `--accent` / `--accent-ink` / `--accent-soft` | `#F0B44C` / `#1A1300` / `#3A3122` | 강조 / 강조 버튼 글자 / 선택 바탕·근거 칩 |
| `--mark` | `#332C1C` | 코드에서 근거로 강조한 범위 |
| `--ok` / `--ok-soft` | `#7FD9A8` / `#18352A` | ‘확인됨’ 표시 |
| `--warn` / `--warn-soft` / `--warn-line` | `#F2C27A` / `#3A2E14` / `#6B5420` | 다시 확인 필요 알림 |
| `--danger` / `--danger-soft` | `#FF9B8F` / `#3D1F1C` | 오류 알림 |

글자 대비는 본문·보조 글자 모두 배경에 대해 4.5:1 이상이어야 한다. `--dim`은 줄 번호에만 쓴다(줄 번호 칸 바탕 `--surface`에서 5.07:1, `--side`에서 5.31:1. `--raised`·`--mark` 위에는 쓰지 않는다). 기획 때 계산한 값: `--muted`는 `--surface` 6.64:1·`--mark` 5.76:1·`--accent-soft` 5.33:1, `--accent`는 `--accent-soft` 6.9:1.

### 3.2 배치

- **왼쪽 아이콘 레일(약 76px):** 보기 다섯 개를 아이콘 + 지금 이름(작은 글씨, 두 줄까지 허용)으로 보인다. 이름과 `aria-current`는 지금 그대로다. 지금 보기는 `--accent-soft` 바탕에 `--accent` 글자.
- **파일 칸:** 레일 오른쪽. 프로젝트 이름, 파일명 검색, 파일 목록(지금 sidebar의 나머지). 고정폭 글꼴, 지금 파일은 한 단계 밝은 바탕.
- **상단 줄:** 브랜드(강조색 글자), 지금 위치(crumbs), 처리 중·파일 설명 진행 표시, ‘프로젝트 폴더 열기’(테두리 버튼), ‘작업 취소·프로젝트 닫기’(글자 버튼). 4단계에서 가운데에 ⌘P 이동 창 버튼이 들어간다.
- **오른쪽 패널:** 탭(‘쉬운 설명’·‘질문’) 모양은 밑줄 탭, ‘패널 접기’는 아이콘 버튼(`aria-label` 유지). ‘설명 패널 펼치기’는 그대로.
- **아래쪽 상태 줄:** 3.6.
- 창 폭이 좁으면 지금처럼 칸이 접히거나 쌓여야 한다. 기존 화면 검사의 1280·1440 배치 확인을 유지하고, 칸을 쌓는 규칙(`styles.css`의 1100px 이하)이 적용되는 폭 하나(예: 1000px)에서 레일·주요 버튼·상태 줄이 겹치거나 잘리지 않는지 확인을 더한다.

### 3.3 버튼과 표시

- 주 버튼(`btn--primary`)은 `--accent` 바탕·`--accent-ink` 글자. 나머지는 테두리 버튼 또는 글자 버튼.
- **근거 버튼은 작은 칩으로 한다.** 질문 답의 `SourceButtons`, ‘답변 근거 코드 보기’, 답변에 제공한 파일 버튼, 개요의 근거 버튼을 `--accent-soft` 바탕·`--accent` 글자·고정폭 12px 칩으로. 글자는 그대로다.
- 태그(`tag--ok`, `tag--unknown`, `tag--doc`)와 알림(`notice`, `notice--info`, `notice--warn`)은 새 토큰으로.
- 코드 읽기 위쪽 도구 줄: 왼쪽은 파일 이름 탭 모양(위에 강조색 선) + ‘읽기 전용’, 오른쪽은 아이콘 버튼(찾기·글자 작게·글자 크게·줄바꿈). ‘코드 15px’ 표시와 `aria-pressed`, `aria-keyshortcuts`는 유지.
- 근거 줄(`data-testid="evidence-range"`)은 코드 위 얇은 경로 줄 모양으로, 글자는 그대로.
- 아이콘은 여러 곳에서 쓰므로 `src/renderer/icons.tsx` 한 파일에 둔다(레일 다섯 개, 찾기, 자물쇠, 줄바꿈, 접기 화살표). 장식 아이콘은 `aria-hidden="true"`.

### 3.4 코드 표시(CodeMirror)

- 코드 읽기(`reader.tsx`)와 변경 보기(`changes.tsx`)가 같이 쓰는 어두운 테마를 `src/renderer/code-theme.ts`에 둔다: `EditorView.theme({...}, { dark: true })`와 `HighlightStyle`. 둘 다 지금의 `defaultHighlightStyle` 대신 이것을 쓴다.
- 문법 색: 키워드 `#C792EA`, 함수·정의 이름 `#82AAFF`, 타입 `#FFCB6B`, 문자열 `#C3E88D`, 숫자 `#F78C6C`, 주석 `--muted`, 나머지 `--ink`. 모든 문법 색은 `--surface`와 근거 강조 바탕 `--mark` 둘 다에서 4.5:1 이상이어야 한다.
- 근거 강조는 지금처럼 선택 범위다. `.cm-selectionBackground`를 `--mark`로 칠한다(화면 검사가 이 클래스를 찾음). 찾기 패널(`.cm-search`)도 어둡게.
- 변경 보기(MergeView)의 바뀐 줄·지운 부분·더한 줄 색을 어두운 바탕에서 구분되게 한다(더함은 초록 계열, 지움은 붉은 계열, 밝기도 달리).

### 3.5 프로젝트 지도

React Flow에 `colorMode="dark"`를 주고, 상자·화살표·점선(거꾸로 가는 연결)·변경 종류 표시를 새 토큰으로 맞춘다. 상자 글자 대비 4.5:1 이상.

### 3.6 아래쪽 상태 줄

**사실인 상태만 적는다.**

- 왼쪽: 자물쇠 아이콘 + ‘읽기 전용’, 프로젝트가 열려 있으면 ‘파일 N개’.
- 오른쪽: ‘AI는 동의한 질문만’(지금 상단 배지를 옮김, `title` 문구 유지), 지금 고른 AI 사용 방식 이름(로컬 워커면 ‘Codex → Gemini → Codex’).
- 넣지 않는 것: 시안에 있던 ‘파일 해시 확인됨’(늘 참이 아님), ‘UTF-8 · LF’(앱이 따로 알려 주지 않음).

## 4 2단계: 동의 문구 접기 (커밋 2)

대상은 세 곳이다: 질문 패널(`ai-panel.tsx`), 파일 설명(`file-explanation.tsx`), AI 개요(`overview.tsx`).

- 체크박스 옆 글자는 **‘보낼 자료에 동의’** 한 줄로 한다.
- 바로 아래에 `<details>`를 두고 `<summary>`는 ‘무엇을 보내나요?’, 안에는 **지금 동의 문장 전체를 그대로**(방식에 따라 바뀌는 받는 곳·관련 파일 문구 포함) 둔다. 처음에는 접혀 있다. 펼침 상태는 기억하지 않는다.
- 체크박스에 `aria-describedby`로 그 전체 문장을 연결해, 접혀 있어도 화면 읽기 프로그램은 전체 문장을 읽게 한다.
- 동의 조건은 그대로다: 체크해야 보낼 수 있고, 보낸 뒤 해제되는 곳은 지금처럼 해제되고, 준비가 안 되면 체크할 수 없다.
- 이 단계는 문구 위치만 바꾼다. 보내는 자료와 동의 규칙은 바꾸지 않는다.
- 확인: 세 곳 모두 처음에 접혀 있고, 펼치면 지금과 같은 문장이 보이며, 체크 없이는 보내기·만들기 버튼이 꺼져 있다. 동의 문장을 찾던 화면 검사는 새 구조에 맞게 고친다.

## 5 3단계: 코드 줄 옆 단계 번호 (커밋 3)

- **어디:** 코드 읽기의 CodeMirror(`reader.tsx`). 함수를 골랐을 때 줄 번호 왼쪽 칸에 그 함수의 단계 번호를 보인다. 흐름 따라가기는 지금 단계의 코드 조각만 보이므로 넣지 않는다.
- **번호:** 왼쪽 단계 목록과 같은 1부터의 번호. 각 단계 근거의 시작 줄(`evidence.startLine`)에 붙인다.
- **한 줄에 단계가 여러 개면** 가장 앞 번호 뒤에 ‘+’를 붙인다(예: `3+`). 누르면 그 줄의 첫 단계를 고른다. 이 묶기 계산은 순수 함수로 두고 단위 시험을 쓴다(같은 줄 묶기, 단계 없음, 함수 없음).
- **지금 단계**는 `--accent` 바탕·`--accent-ink` 글자, 나머지는 `--raised` 바탕.
- **누르면** 왼쪽 목록에서 그 단계를 누른 것과 같다(`showEvidence(step.evidence, step.id)`). 잠김(`busy`·`stale`)이면 눌러도 아무 일도 하지 않는다.
- 표시는 지금 열린 파일의 분석 결과(`source.analysis`)의 함수일 때만 한다. 함수 선택을 풀거나 파일이 바뀌면 지운다.
- 마커에 `title`로 ‘3단계 · 조건 확인’처럼 단계 이름을 붙인다. 마커는 키보드로 가지 않으며, 키보드 경로는 지금의 단계 목록이다.
- 확인(화면 검사): 함수를 고르면 마커 수가 단계 시작 줄 수와 같고, 지금 단계 마커가 강조되며, 마커를 누르면 `evidence-range`가 그 단계의 줄로 바뀐다.

## 6 4단계: ⌘P 이동 창 (커밋 4)

- **여는 법:** 상단 줄 가운데의 검색창 모양 버튼 ‘파일·함수로 이동 ⌘P’, 또는 ⌘P. 프로젝트가 열려 있고 처리 중이 아닐 때만 열린다. 이미 열려 있으면 다시 열지 않는다. 앱 메뉴에 ⌘P를 쓰는 항목이 없는지 확인한다.
- **창:** `<dialog>`를 `showModal()`로 연다. 입력 칸(`aria-label` ‘파일·함수 이름으로 이동’) 아래에 결과 목록. 위·아래 화살표로 고르고 Enter로 열며, Esc로 닫고 연 버튼으로 초점을 돌려준다.
- **찾는 범위:** 프로젝트 파일 경로 전체와 **지금 열린 파일의 함수 이름**만. 대소문자 무시, 포함 검색. 다른 파일의 함수는 그 파일을 읽어야 알 수 있고 지도에도 전체 함수 목록이 없으므로 넣지 않는다. 입력 아래에 ‘파일 이름과 지금 파일의 함수에서 찾아요.’를 한 줄로 보인다.
- **결과:** 함수 먼저, 그다음 파일. 최대 50개. 빈 입력이면 지금 파일의 함수와 파일 목록 앞부분.
- **고르면:**
  - 파일: 왼쪽 파일 목록에서 누른 것과 똑같이 한다(흐름 따라가기면 그 보기에 머물고, 아니면 코드 읽기로. 질문 대상을 비우는 규칙도 같음).
  - 함수: 코드 읽기의 함수 버튼을 누른 것과 같이 한다(`selectSymbol` + `showEvidence`). 지금 보기가 흐름 따라가기면 머물고, 아니면 코드 읽기로.
- **잠김 조건은 지금 함수 버튼과 같다.** 함수 결과는 `busy || stale`이면 꺼진 상태로 보이고, 고르는 순간에도 다시 확인해 그 조건이면 `selectSymbol`부터 하지 않는다(`showEvidence`는 `stale`이면 바로 멈추므로, 먼저 선택을 바꾸면 선택만 바뀌고 근거는 안 바뀐다). `stale`일 때 입력 아래에 ‘코드가 바뀌어 함수는 파일을 다시 읽은 뒤 고를 수 있어요.’를 보인다. 파일 결과는 `stale`이어도 열 수 있다(파일 목록처럼 다시 읽기가 최신 코드로 이어 줌). `busy`면 파일 결과도 꺼진다.
- 확인(화면 검사): 프로젝트가 없으면 버튼이 꺼져 있고 ⌘P가 아무 일도 하지 않음, ⌘P로 열림, `order`를 치면 `order.ts`가 보이고 Enter로 열림, 함수 결과를 고르면 그 함수가 선택되고 근거 줄이 바뀜, Esc로 닫히고 초점이 돌아옴, **창이 열린 동안 파일 변경이 감지되면 함수 결과가 꺼지고 골라도 선택이 바뀌지 않으며 파일 결과로는 다시 읽을 수 있음.**

## 7 단계마다 할 일

- 각 단계는 따로 구현·검사·커밋한다. 앞 단계가 커밋된 뒤 다음 단계를 시작한다.
- 단계마다 순서: 구현 → 아래 검사 → Claude가 diff와 스크린샷 검토 → 지적 반영과 다시 검사 → 커밋 전 검사 기록(`verify.mjs`) → 커밋. 2단계(동의 문구)는 사용자에게 보내는 자료의 안내를 바꾸므로 커밋 전에 Codex `security` 검토도 받는다.
- 각 단계 끝에 `npm run typecheck`, `npm test`, `npm run package`, `npm run test:electron`, `npm run test:packaged`를 실행한다. 화면 검사는 서로의 창 포커스에 영향을 주므로 순서대로 돌린다.
- README의 화면 설명(‘개발 역할과 화면 연결 기준’ 안의 화면 설명 부분)과 `docs/implementation-status.md`에 그 단계에서 바뀐 것만 짧게 적는다.
