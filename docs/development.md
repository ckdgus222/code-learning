# Code Learning 개발 문서

사용자용 소개와 설치 방법은 [README](../README.md)에 있습니다. 이 문서는 기능의 자세한 동작, AI 연결 구현, 알려진 한계 전체, 화면과 main 사이 계약, 코드 위치를 기록합니다. 시험 기록은 [구현 상태](implementation-status.md)에 있습니다.

## 현재 가능한 일

- 폴더 선택 → 제외 이유·접고 펼치는 폴더 트리 → 파일명 검색 → 실제 코드 읽기
- 한눈에 보기: 루트 README(`.md`·`.txt`)의 첫 소개 문단을 ‘문서에 적힌 소개’로 표시(일반 텍스트, 코드와 맞는지는 미확인). 아래에서 프로젝트 구성과 기능 목록을 볼 수 있습니다. `package.json`의 main·bin, index·main·app 파일, export된 함수에서 고른 ‘학습 시작점 후보’를 누르면 함수 안 순서로 이동
- 파일 안내: TS/JS 파일을 열면 **이 파일은** 카드에서 코드 모양으로 짐작한 역할을 봅니다. 카드를 펼치면 근거·함수·덩어리 안내도 AI 없이 볼 수 있습니다. 코드 보기로 질문 대상을 유지하며 원문을 강조하고, 이 함수 고르기로 질문할 함수를 선택할 수 있습니다.
- 파일 설명: TS/JS 코드 읽기에서 **이 파일 설명 만들기**를 누르고 동의하면, 파일이 하는 일과 가져오기·클래스·필드·함수 같은 덩어리마다 1~3문장 설명을 받습니다. 질문 패널의 설정에서 고른 AI 하나가 설명하며 ‘AI 대조 없음’으로 표시합니다. 덩어리는 최대 80개이며 생략·구문 오류를 표시합니다. 파일 전체·덩어리의 코드 보기는 파일 해시를 다시 확인하고 범위를 강조하며 질문 대상과 답변을 유지합니다. 함수와 직접 이어진 덩어리의 설명은 함수 안 순서와 코드 읽기에도 보입니다. 받아들인 설명은 앱 데이터 폴더의 SQLite(`learning.sqlite`)에 파일마다 자동 저장되어 앱을 다시 열어도 AI 없이 보이고, ‘저장됨 · 날짜’ 옆 **지우기**로 지웁니다. 만든 뒤 파일이 바뀌었으면 ‘다시 확인 필요’와 함께 보이고 근거 이동을 막습니다. 저장할 때 덩어리 이름의 비밀값처럼 보이는 형태는 가립니다.
- AI 기능 정리: 기능별 안내의 **AI로 기능 정리하기** → 설치 확인 → 동의 후, 프로젝트 요약과 기능 묶음·이름·한 문장 설명을 받습니다. 질문 패널의 설정에서 고른 AI 하나가 정리하며 ‘AI 대조 없음’으로 표시합니다. 한 기능에 주소가 여럿이면 확실한 프론트 연결이 가장 많은 주소부터 열고, 주소 버튼으로 각각의 이야기를 볼 수 있습니다. 빠진 주소는 ‘정리되지 않은 기능’에 남습니다. 결과는 프로젝트마다 하나 자동 저장되어 주소를 다시 찾거나 앱을 다시 열어도 보이고, **지우기**로 지웁니다. AI에 보낸 목록이나 그 주소·요청 코드가 바뀌었으면 ‘다시 확인 필요’와 요약만 보이고 기능 묶음에는 적용하지 않습니다(목록 원문 대신 해시만 저장).
- TS/JS 함수·화살표 함수·메서드 선택 → 조건문·반환문 등 구문 → 해당 원본 범위 강조
- 함수 안 순서(`function`): 함수 하나를 코드에 적힌 순서대로 한 단계씩 보기. 받는 값, 반환·오류 던지기 위치, 확인하는 조건·돌려주는 값, if의 맞으면/아니면 단계로 이동, 이전/다음, 코드 읽기와 왕복
- 흐름 따라가기(`flow`): 한눈에 보기나 기능 목록에서 기능을 고르면 **화면 → 프론트 처리 → 요청 → 서버 받는 곳 → 서버 처리 → 저장소 → 화면 결과**의 단계별 이야기를 봅니다. 화면 근거가 없으면 ‘시작·코드 처리·요청 뒤 처리’로 표시합니다. 찾지 못한 단계는 빼고 요청마다 이야기를 나눕니다. 각 단계에서 코드와 관련 함수·다른 호출 경로를 보고, **이 함수 안 순서**로 이동할 수 있습니다. 코드 위치는 파일 해시를 다시 확인하고 강조하며 질문 대상은 유지합니다. 반복 호출은 멈춤 안내를 표시합니다. **전체 그림과 단계 보기**를 펼치면 기능 지도와 단계 목록이 나옵니다.
- 프로젝트 지도 — **기능별 연결**: 기본 탭입니다. 기능을 고르면 ‘화면 쪽 → 요청 → 서버 쪽’의 세 칸 지도로 봅니다. 노드를 누르면 해당 코드 범위를 확인할 수 있고, **흐름 따라가기에서 단계별로 보기**로 이동할 수 있습니다. 타입으로 찾은 연결과 추정 연결은 선 모양으로 구분합니다.
- 프로젝트 지도 — **파일 연결**: 파일끼리 가져다 쓰는 관계(import)를 그림으로 봅니다. **설계 보기**는 폴더끼리 연결과 개수, **파일 보기**는 파일끼리 연결을 보여 줍니다. 다른 폴더를 쓰는 폴더가 왼쪽, 쓰이는 폴더가 오른쪽이고 거꾸로 가는 연결은 점선입니다. 화살표·목록에서 해당 import 코드로 이동합니다. 지도를 만든 뒤 파일이 바뀌었으면 강조하지 않습니다. 지도는 별도 작업자가 만들며, 그동안에도 파일을 열거나 지도 만들기를 취소할 수 있습니다.
- 프로젝트 지도 — **분석 한계**: 실행 순서가 아니라 TS/JS의 정적 import 연결입니다. 상대 경로와 지원하는 경로 별칭 중 대상을 하나로 확정할 수 있는 연결만 잇습니다. 경로 별칭은 짧은 이름으로 파일 위치를 가리키는 설정입니다. `tsconfig.json`·`jsconfig.json`의 `paths`·`baseUrl`과 프로젝트 안 상대 경로 `extends`를 읽습니다. 패키지 `extends`·`references`, 별도 접미사를 붙이는 `moduleSuffixes`, `node16`·`nodenext` 방식의 별칭은 따라가지 않습니다. 후보가 여럿이거나 선언 파일·패키지 해석이 필요하면 확정하지 않습니다. 상대 경로의 `.js`·`.jsx`·`.mjs`·`.cjs` import는 TS 짝 파일도 후보에 넣습니다. 잇지 못한 것은 이유·후보와 함께 **확인 못 함** 또는 **외부 패키지 또는 경로 별칭**에 남습니다.
- 기능별 안내의 범위: TS/JS의 NestJS·Next API·Express 모양과 fetch·axios·첫 경로 매개변수를 그대로 넘기는 감싼 함수를 찾습니다. 주소 글자로 찾은 연결이며 실제 실행을 확인하지 않습니다. 앞부분·경로 값·방식이 불명확하거나 후보가 여럿이면 이유와 함께 **추정**으로 표시하고 확실한 연결 수에서 뺍니다. 훅 결과 사용도 추정입니다. 다른 서버 주소는 잇지 않습니다. Fastify·Hono·Koa, 다른 언어, `app.use`의 마운트 경로는 따라가지 않습니다. 파일 연결과 같은 경로 별칭 설정을 읽고, 대상을 하나로 확정할 수 있을 때만 따라갑니다. 일부 파일을 읽지 못하면 Nest와 axios 앞 경로를 확정하지 않습니다. 프론트 함수 12개·요청 5개·백엔드 함수 10개(깊이 3)까지 표시하며 취소·다시 찾기가 가능합니다. 이야기 문장은 코드 글자로 만든 것이며 실제 동작의 뜻을 해석하지 않습니다. 기본 연결 분석은 AI 없이 합니다. 동의하면 주소·이름 목록으로 AI 기능 정리를 요청할 수 있습니다.
- 함수 호출 관계: 함수 안 순서에서 함수를 고르면 ‘부르는 것’(이 함수 본문의 호출)과 ‘부르는 곳’(프로젝트에서 이 함수로 이어진 호출)을 보여 줌. 이름이 가리키는 가장 가까운 선언을 찾아, 같은 파일 함수·다시 대입되지 않은 `const`/`let` 함수·상대 경로나 지원하는 경로 별칭으로 가져와 정확히 하나로 정해지는 내보낸 함수만 잇고, 같은 클래스의 `this.m()`과 타입이 적힌 `this.f.m()`은 ‘타입으로 찾음’으로 따로 표시하고 이동할 수 있음(확정된 부르는 곳·들어오는 값에는 넣지 않음). 그 밖의 멤버 호출·매개변수·`var`·다시 대입·다시 내보내기 등은 이유와 함께 ‘확인 못 함’, 설정으로 풀지 못한 비상대 경로 가져오기는 ‘외부 패키지 또는 경로 별칭’. ‘그 함수로’·‘호출 위치’로 이동(찾은 뒤 파일이 바뀌었으면 움직이지 않음). 실행 순서·실제로 불리는지는 아님. 별도 작업자가 지도와 같은 한도로 찾고 취소할 수 있음
- 값 따라가기: 함수 안 순서에서 함수를 고르면 그 함수의 매개변수·안에서 만든 이름·바깥에서 쓰는 이름을 버튼으로 보여 주고, 누르면 선언 위치와 종류, 적힌 타입, 고정 값(`const`로 바로 적은 글자 그대로의 값), 처음 값과 그 선언에 대한 대입(식 그대로, 위치와 함께), 매개변수면 확정된 부르는 곳에서 그 자리에 넘긴 인자(테스트 파일의 것은 ‘테스트 예시’로 따로)를 보여 줌. 가져온 이름은 내보낸 쪽 선언까지 따라감. 실행한 값이나 계산 결과가 아니라 코드에 적힌 값과 식만 보이며, 정할 수 없으면 이유와 함께 ‘확인 못 함’
- 값의 모양: 값 따라가기에서 TypeScript 타입 검사기가 코드에서 읽은 ‘모양’(타입)을 함께 보여 줌. 고른 함수가 ‘돌려주는 값의 모양’(`"ok" | "too many"` 등)과 이름 카드의 ‘모양’(`Item[]`, `{ items: Item[]; total: number; }`). 실행하지 않으며, 진짜 `any`가 섞이면 ‘모양을 알 수 없는 부분’이라고 알림. 검사기는 이미 쓰던 `typescript` 7.0.2(tsgo, 버전 고정)를 앱 밖 별도 프로세스로 띄우고, 모든 파일 접근을 앱이 같은 읽기 규칙으로 답함. **사용자 결정으로 이 확인에 한해 `node_modules` 안의 타입 파일(`.d.ts`·`.d.mts`·`.d.cts`·`package.json`)만 프로젝트 폴더 안에서 읽음**(원문은 화면·AI에 보내지 않음, 폴더 밖을 가리키는 링크·하드 링크·비밀 이름은 거절). V-1이 정하지 못한 이름이나 V-1과 다른 선언을 찾은 가져오기에는 모양을 붙이지 않음
- 변경 보기: macOS의 ‘달라진 내용’에서 기준 커밋(기본은 HEAD, 열린 폴더를 바꾼 최근 커밋 100개)을 고르면 지금 파일과 비교해 수정·추가(스테이징됨)·미추적·삭제·이름 변경(내용이 같은 이동만)을 목록으로 보여 주고, 고른 변경은 이전 코드와 지금 코드를 나란히 비교(`@codemirror/merge`, 읽기 전용, 바뀌지 않은 부분 접기). 프로젝트 지도의 상자에도 종류를 표시하고 지도 아래 ‘변경 목록’에 삭제·이름 변경 전 경로까지 모두 보여 줌. 설치된 git(개발 도구·Homebrew의 고정 위치)을 **쓰기·네트워크·다른 프로그램 실행을 막은 샌드박스** 안에서 읽기 명령(`rev-parse`·`log`·`ls-tree`·`ls-files`·`cat-file`)으로만 쓰고, 저장소 설정이 프로그램을 띄우지 못하게 안전 설정과 깨끗한 환경 변수로 실행하며, 비교는 앱이 직접 계산(`diff`·`status`를 쓰지 않음). 브랜치·인덱스·파일을 바꾸지 않음. 제외 규칙에 해당하는 경로(`.env`, `dist/` 등)는 내용을 읽지 않고 개수와 이유만. 열린 폴더 위에 저장소가 있어도 쓰되(사용자 결정) 열린 폴더 안 경로만 비교·표시. 사람이 바꿨는지 AI가 바꿨는지는 가려내지 않음. **Windows에서는 v1.0의 변경 보기(git)를 사용할 수 없습니다.**
- AI 개요(기능과 구성): 한눈에 보기에서 시작 파일 하나(README·시작점 후보·모든 파일 중에서, 없어도 됨)를 고르고 동의하면 질문 패널의 설정에서 고른 AI 하나가 개요를 만듦. 같은 AI가 파일 목록에서 최대 4개를 골라 앱이 읽고, ‘이 프로젝트가 하는 일’·‘주요 기능 후보’·‘큰 구성과 역할’·‘확인하지 못한 것’을 씀. 다른 AI의 대조는 없으며 ‘AI 대조 없음’으로 표시함. 모든 설명에 근거 버튼(읽은 파일 전체, 세부 위치 미확인)이 붙고, AI가 적은 함수 이름은 앱이 그 파일에 실제로 적혀 있을 때만 남김. 읽은 파일이 없으면 개요를 쓰지 않고 ‘개요 작성 안 함’으로 표시함. 실행 중 자료가 바뀌거나 응답 형식·근거 검사가 실패하면 결과를 표시하지 않음. ‘조사 범위’에 실제로 읽은 파일과 읽기 제한을 보임. 조사한 범위의 개요이고 정확성을 보장하지 않으며, AI가 묶은 역할은 지도 선이 되지 않음. 개요는 프로젝트마다 하나 자동 저장되어 앱을 다시 열어도 보이고 **지우기**로 지움. 읽은 파일이 바뀌었거나 없어졌으면 ‘다시 확인 필요’와 함께 근거·따라가기를 막음
- 기획 대조: 한눈에 보기의 **기획과 비교 열기** → 기획 문서(`.md`·`.markdown`·`.txt`) 선택 → 설치 확인·동의 → **대조하기**로 시작합니다. 256 KiB를 넘는 문서는 열지 않습니다. 기획은 최대 48 KiB까지 보내며, 그보다 큰 문서는 장·절이나 줄 범위를 고릅니다. 프로젝트 파일 목록(96 KiB 한도)과 지도 연결(64 KiB 한도)도 보내며, 한도를 넘으면 일부만 보냅니다. AI가 고른 코드는 최대 8개·파일당 32 KiB·합계 80 KiB입니다. 설정에서 고른 AI 하나가 파일을 고른 뒤 기획과 코드를 대조합니다. 다른 AI의 검토는 없으며 ‘AI 대조 없음’으로 표시합니다.
  - 결과는 기획대로·다름·확인 못 함·못 찾음과 시키지 않은 작업 후보·설계와 다른 연결로 나눕니다. 읽은 파일과 목록만 본 파일, 보내지 않은 기획 범위와 읽기 제한도 표시합니다. **‘못 찾음’은 조사한 범위에서 못 찾았다는 뜻이며, 구현이 없다는 확정이 아닙니다.**
  - 결과와 보낸 기획 글(비밀값처럼 보이는 내용은 가림), 문서 경로를 이 컴퓨터의 SQLite에 프로젝트마다 하나 자동 저장합니다. 다시 열어도 보이며 **지우기**로 삭제합니다. 저장에 실패하면 오류를 표시하고, 앱을 닫으면 결과가 사라집니다.

- 개요 안 찾기: 개요의 기능 후보·구성 역할 이름과 설명, 지금 학습 주제 이름에서만 찾음(프로젝트 전체 검색이 아니라는 범위를 함께 보임)
- 학습 주제: 개요의 ‘이 기능 따라가기’, ‘어디부터 읽을까요?’의 시작점 후보, 지금 고른 함수의 ‘이 함수에서 학습 시작’으로 주제를 세움. 화면 위 주제 바에서 학습 이름 바꾸기, ‘출발점으로’, ‘이전 위치’(주제 안에서 본 곳 최근 20개, 파일이 그대로일 때만 강조 범위와 함수를 되살리고 바뀌었으면 파일만 염), ‘시작·처리·결과 질문 준비’(그 함수를 질문 대상으로 하고 질문 칸만 채움, 동의는 다시 받고 새 대화로 보냄, 답에 ‘학습 주제’ 표시), ‘한눈에 보기로’(그 카드로 초점), ‘주제 닫기’. 출발점은 파일이 그대로일 때만, 위치를 알면 이름과 위치로, AI 후보는 그 이름의 함수가 하나일 때만 고르고 아니면 파일만 염. 주제 안에서 움직여도 질문 대상과 답은 그대로
- 어려운 코드 표시: 함수 본문의 코드 줄이 60줄을 넘거나 if·반복·switch·try 중첩이 4단계를 넘으면 코드 읽기의 함수 옆에 ‘긴 함수 · 84줄’, ‘깊은 중첩 · 5단계’처럼 표시. 프로젝트 지도 아래 ‘어려운 코드 살펴볼 곳’에 지도가 본 모든 TS/JS 파일의 해당 함수를 모아 보여 주고, 누르면 그 함수로 이동. 표시는 살펴볼 곳일 뿐 나쁜 코드 판정이 아님. 표시된 함수를 고르면 ‘AI에게 단순하게 쓰는 법 묻기’로 함수 전체를 질문 대상으로 하고 질문 칸을 채움(보내기·동의는 직접, 앱은 코드를 고치지 않음)
- 한글·이모지·BOM·CRLF를 유지한 코드 위치 확인
- 기존 파일·제외 규칙 변경 감지, 근거 사용 전 해시 재검사
- 프로젝트 전환·취소 시 분석 worker와 감시 정리
- SQLite에 연 프로젝트 식별 정보, 학습 위치·기록, AI 파일 설명·개요·기능 정리·기획 대조·질문과 답 저장(프로젝트마다 최근 50개 답, 답마다 삭제 가능)
- 질문 패널의 설정에서 Codex 단독(기본값)·Gemini 단독(Antigravity)·Claude Code 단독(준비 중) 선택, 설치 위치·버전 확인
- 앱 설정(톱니)의 **새 버전 확인**을 누를 때만 `src/main/update-check.ts`가 `net.fetch`로 고정 주소 `https://api.github.com/repos/ckdgus222/code-learning/releases/latest`에 요청합니다. 앱 시작이나 설정 열기에는 요청하지 않습니다. 시스템 프록시를 따르며 `credentials: 'omit'`으로 쿠키·인증 정보를 제외하고, 프로젝트·이메일·기기 정보도 보내지 않습니다. 앱 버전은 User-Agent에 포함합니다. 진행 중 요청은 하나를 공유하고, 시간은 10초(`AbortSignal.timeout`), 본문은 최대 1 MB(1,048,576바이트, 선언된 길이와 실제 읽은 길이 모두 검사)로 제한합니다. `tag_name`의 세 숫자 버전만 비교하며, 404는 공개 버전 없음으로 표시합니다. 결과는 화면 상태에만 둡니다. **내려받기 페이지 열기**는 `https://github.com/ckdgus222/code-learning/releases/latest`만 열고 응답의 `html_url`은 사용하지 않습니다. 자동 내려받기·설치는 없습니다.
- 버전 확인 시험은 실제 인터넷을 쓰지 않습니다. `tests/update-check.test.ts`는 가짜 fetcher를 전달하고, `tests/view-settings-main.test.ts`는 main을 가져오기 전에 Electron `net.fetch`·`shell.openExternal`과 전역 `fetch`를 가짜로 등록해 창 생성까지 호출이 없는지 확인합니다. `scripts/view-settings-smoke.mjs`의 공용 Electron 검사는 `app.evaluate`에서 `net.fetch`·`shell.openExternal`을 기록하는 가짜로 바꿉니다. 이 검사의 보장 범위는 교체 이후이며, 설정을 열기만 하면 0회, 확인 버튼을 누르면 API 요청 1회, 내려받기 버튼을 누르면 고정 페이지 열기 1회인지 확인합니다. 이를 위해 구현은 호출할 때마다 `net.fetch`를 조회합니다.

프로젝트 목적·기능·구성은 사용자가 동의해 만든 AI 개요(조사한 범위)와 AI 기능 정리(주소·이름 목록)로 설명하고, 실제 실행 흐름은 자동으로 설명하지 않습니다. 구문 목록을 실행 순서나 AI 설명으로 표시하지 않습니다. **macOS에서는 Codex 단독·Gemini 단독 질문을 쓸 수 있고, Windows에서는 Codex 단독만 실험 기능으로 열려 있습니다. Claude Code 단독은 잠겨 있습니다. 질문 패널에서 동의한 질문만 보냅니다. 보내기 전에 아래 ‘알려진 한계’를 읽어 주세요.**

## 단독 AI 연결 구현

기본 사용 방식은 **Codex 단독**이며, macOS에서는 Gemini 단독(Antigravity)도 고를 수 있습니다. Gemini 요청 모델은 `gemini-3.8-flash-high`로 고정하고 다른 모델로 자동 전환하지 않으며, Google AI Studio API 키로만 연결합니다. Claude Code 단독은 아직 준비 중입니다. **로컬 워커는 2026-11-07 사용자 결정으로 제거했습니다.** 예전에 저장한 결과는 계속 열 수 있으며 ‘로컬 워커(이전 방식)’으로 표시합니다.

프로젝트를 열고 상단 **질문 → 설정 → 로컬 AI 설치 확인**을 누르면 기본 설치 위치에서 공식 프로그램의 `--version`만 실행합니다. macOS에서는 Codex와 Antigravity의 설치 확인도 아래의 울타리 안에서 합니다. Windows Codex는 이 울타리 없이 확인합니다. 설치 여부·버전을 확인해도 로그인 성공이나 실제 AI 연결 성공으로 표시하지 않습니다. 기본 위치 밖의 사용자 지정 실행 파일 선택은 아직 제공하지 않습니다.

질문 입력·전송 동의·진행 단계·AI 작업 취소·근거가 있는 응답 표시를 구현했습니다. 설치 확인에서 고른 실행기(Codex 또는 Antigravity)를 찾아야 시작할 수 있습니다. 코드 질문·파일 설명·기능 정리는 한 AI가 바로 작성합니다. AI 개요와 기획 대조는 같은 AI가 파일을 고른 뒤 작성합니다. 새 결과는 다른 AI의 대조가 없어 ‘AI 대조 없음’으로 표시합니다. 범위 밖 파일·셸·웹·MCP 접근 차단을 확인하는 C04 시험은 원래 기준(모든 칸 ‘차단’)을 통과하지 못한 채 열었으므로, 남은 빈칸을 아래 ‘알려진 한계’에 적었습니다. UI나 환경변수로 준비 검사를 우회하는 옵션은 없습니다. 흐름 테스트는 가짜 응답을 사용하며 실제 계정 연결 검증을 대신하지 않습니다.

AI로 보낼 코드와 질문(이전 질문 포함)은 프롬프트에 넣기 직전에 흔한 비밀값 형태(개인키 블록, AWS·GitHub·`sk-`·Google·Slack·Stripe 토큰, JWT, 접속 문자열 비밀번호, password·token·secret·api key 같은 이름에 넣은 값)를 `[MASKED_SECRET]`으로 가리고, 가린 파일·질문을 답변의 ‘읽기 범위’에 알립니다(`src/core/ai/secrets.ts`). 원본은 바꾸지 않으며 모든 비밀값을 찾는다고 보장하지 않습니다.

코드 질문은 선택한 함수/구문에서 시작하며 **선택한 코드가 있는 파일만 읽습니다.** 선택 범위와 파일 전체는 각각 최대 32 KiB이며, 파일 전체를 보내지 못하면 이유를 표시합니다. 이어 묻기에서도 다른 파일을 더 읽지 않습니다. AI 개요와 기획 대조에서는 고른 AI가 허용된 파일 목록의 ID를 요청하고, 앱이 제외 규칙을 다시 확인하여 읽습니다. AI가 직접 경로나 셸 명령을 실행해 읽는 방식은 아닙니다.

답변은 원래 근거와 읽은 파일들의 해시에 연결합니다. AI 실행 전과 최종 표시 전에 변경 여부를 확인합니다. 코드가 바뀌거나 응답 형식·근거 검사가 실패하면 답변을 표시하지 않습니다. 답변의 근거로 이동해도 질문 기준과 답변을 유지합니다. 호출의 ‘그 함수로’·‘호출 위치’, 값 위치, 지도·변경 보기·한눈에 보기에서 코드로, 학습 주제 안에서 이동해도 마찬가지이며, 질문 대상은 함수·구문 버튼을 직접 누르거나 기능 질문을 준비할 때(또는 파일 목록에서 파일을 열 때 비워짐)만 바뀝니다. 답의 단계와 코드 설명마다 그 근거 버튼이 바로 아래에 있습니다. 선택한 코드는 행 범위로, 통째로 읽은 파일은 ‘파일 전체 근거 · 세부 위치 미확인’(문서는 ‘문서 전체’)으로 보입니다. 새 코드 선택은 새 대화가 됩니다. 질문과 답은 프로젝트마다 최근 50개까지 이 컴퓨터의 SQLite에 자동 저장하며, ‘지난 질문과 답’에서 다시 열거나 지울 수 있습니다. 코드가 바뀐 답은 경고와 함께 보이고 근거 열기는 막습니다. 이어 묻기는 앱을 켜 둔 동안만 가능하며 지난 답의 대화는 이어지지 않습니다. 로컬이라는 말은 실행기가 이 컴퓨터에서 동작한다는 뜻이고, 모델의 답변 생성은 제공자 서버에서 이뤄집니다.

macOS의 원본 쓰기 차단은 비밀 없는 임시 파일에서 확인했습니다. `npm run test:ai-sandbox`는 읽기 허용, 수정·생성·삭제·이름 변경·하위 프로세스 쓰기 차단을 검사합니다. **이 검사는 실제 AI 실행기의 로그인·도구 제한 검증을 대신하지 않습니다.**

macOS의 AI 질문 단계와 Codex·Antigravity 설치 확인은 `sandbox-exec` 울타리 안에서 실행합니다(`src/core/ai/fence.ts`). 도구 제한이 뚫려도 CLI는 사용자 홈·`/Users`·`/Volumes`·`/private/tmp`·사용자별 임시 폴더(`/private/var/folders`)의 파일 내용을 읽지 못합니다. 예외는 자기 앱 전용 홈, 이번 실행 임시 폴더, 자기 프로그램 파일뿐입니다. 쓰기는 자기 앱 전용 홈·실행 임시 폴더와 출력 버리기용 `/dev/null`만 허용합니다. Codex와 agy는 서로의 앱 전용 홈을 읽지 못합니다. macOS에서 울타리를 씌울 수 없으면 AI를 실행하지 않습니다. 다른 프로그램의 Unix 소켓과 로컬 서비스(`localhost`) 연결, 울타리 밖 프로세스로 신호 보내기, 다른 앱 열기·제어(`open`, Apple Events), `security`·`launchctl`·`crontab`·`at`·`batch` 명령 실행, 클립보드 읽기도 막습니다. IPv6 연결도 모두 막습니다. macOS 26에서는 IPv6 형태의 내 컴퓨터 주소(`::ffff:127.0.0.1`)가 `localhost` 차단을 빠져나갔기 때문입니다. 그래서 모델 API는 IPv4로만 연결하며, IPv6만 쓰는 네트워크에서는 AI가 연결되지 않을 수 있습니다. DNS용 mDNSResponder 소켓은 예외로 허용합니다. `/etc`·`/Library` 등 차단 경로 밖 파일 읽기와 다른 프로그램을 통한 Keychain 서비스 접근은 막지 않습니다. Keychain 서비스까지 막으면 Codex가 실행되지 않아 열어 두었고, 해당 프로그램을 신뢰하지 않는 항목은 macOS가 사용자에게 확인합니다. `sandbox-exec`는 Apple이 사용 중단으로 표시한 도구입니다.

**Windows는 예외입니다. Codex 단독만 울타리 없이 실행하는 미검증 실험 기능입니다.** 질문·파일 설명·기능 정리·AI 개요·기획 대조를 Codex 단독으로 실행할 수 있습니다. macOS와 같은 파일 접근 제한이 없으며, 도구 차단이 실패하면 Codex가 이 컴퓨터의 파일을 읽거나 바꿀 수 있습니다. 실제 Windows PC의 로그인·AI 연결·접근 제한은 미검증입니다. Windows에서는 Gemini 단독을 잠가 두었습니다.

## 알려진 한계

질문을 보내기 전에 알아 둘 것입니다. macOS의 Codex·Gemini 단독은 앱 전용 홈·울타리를 쓰지만 아래 한계가 있습니다. Windows Codex는 앱 전용 홈을 쓰지만 이 울타리는 없습니다. 시험 기록은 [구현 상태](implementation-status.md)에 있습니다.

- **시험한 버전:** Codex 0.163.0, Antigravity(agy) 1.4.3. Codex는 설치된 버전을 보여 주며 버전이 달라도 막지 않습니다. Gemini는 Antigravity(agy) 1.4.12 이상에서만 실행합니다. CLI가 업데이트되면 도구와 동작이 바뀔 수 있으니 연결 시험(`npm run test:codex-live`, `npm run test:agy-live`)을 다시 하는 것을 권합니다.
- **도구 차단은 시험한 범위만 확인했습니다.**
  - Codex는 로그인 상태에서 제공 도구 목록을 알려 주지 않습니다. 대놓고 시켜도 도구를 시도하지 않아 차단을 직접 보지 못했습니다. 가짜 서버로 강제로 부른 시험에서는 파일·셸·웹·하위 에이전트 도구가 거절됐지만, MCP 자료 조회 도구 3개는 실행됐습니다(연결된 서버가 없어 빈 결과). Code Mode의 `exec` 도구는 남아 있습니다.
  - Antigravity는 제공 도구 60개 중 시도한 것(파일 읽기·쓰기, 셸, 웹 검색, MCP 호출)이 앱 훅이나 거부 규칙에 거절됐지만, 60개 전부를 시험하지는 않았습니다. 1.4.3 실계정 시험에서는 밖 파일 편집 1건이 거절이 아닌 원인 모를 오류로 끝났습니다(실제 변경 없음). 가짜 서버로 강제로 부른 시험(API 키 방식)에서는 모델에게 알리는 도구 12개를 모두 불렀고, 샌드박스 우회 요청을 포함해 모두 앱 훅에 거절됐습니다.
  - 앱은 도구나 다른 작업 단계를 보고한 답을 버리지만, 이미 일어난 일을 되돌리지는 못합니다.
- **macOS 울타리가 막는 것과 막지 않는 것:** 홈·`/Users`·`/Volumes`·`/private/tmp`·사용자별 임시 폴더(`/private/var/folders`)의 파일 읽기와 허용 폴더 밖 쓰기를 막습니다. 다른 프로그램의 소켓·로컬 서비스(`localhost`) 연결, 밖 프로세스로 신호 보내기, 앱 열기·제어(`open`, Apple Events), `security`·`launchctl`·`crontab`·`at`·`batch` 실행, 클립보드 읽기도 막습니다. IPv6 연결도 막습니다(IPv6만 쓰는 네트워크에서는 AI가 연결되지 않을 수 있습니다). **IPv4 인터넷 전송, `/etc`·`/Library` 등 차단 경로 밖 파일 읽기, 다른 프로그램을 통한 Keychain 서비스 접근은 막지 않습니다.** DNS용 mDNSResponder 소켓은 허용하며, Keychain에서 해당 프로그램을 신뢰하지 않는 항목은 macOS가 사용자에게 확인합니다. Windows Codex에는 이 울타리가 없으며, 실제 PC에서의 접근 제한도 미검증입니다.
- **보내는 자료:** AI 기능 정리는 프로젝트 이름과 앱이 찾은 서버 주소·요청·Next 화면 목록(파일 경로·함수 이름 포함)만 보냅니다. 코드 원문과 README 소개는 보내지 않습니다. 전체 목록이 32 KiB를 넘으면 순서대로 잘라 ‘일부만 보냄’을 표시합니다. 이 정리는 주소·이름만 보고 쓴 추정이며 실제 구현이나 정확성을 보장하지 않습니다. 파일 설명은 해당 파일의 경로·원문(최대 32 KiB)과 앱이 나눈 덩어리 목록(ID·종류·이름·행 범위)만 보냅니다. 다른 파일은 보내지 않습니다. 질문할 때는 선택한 코드와 그 파일 전체(크기 제한 안), 프로젝트 파일 목록, 질문, 최근 답변을 보냅니다. 질문에서는 다른 파일을 더 읽지 않습니다. AI 개요는 프로젝트 파일 목록, 고른 시작 파일(0~1개), AI가 고른 파일(최대 4개)을 설정에서 고른 AI 하나에 보냅니다. 기획 대조는 고른 기획 범위(최대 48 KiB), 파일 목록·지도 연결, AI가 고른 코드(최대 8개·파일당 32 KiB·합계 80 KiB)를 보냅니다. 기획 대조의 파일 목록은 96 KiB, 지도 연결은 64 KiB 한도이며, 넘으면 일부만 보냅니다. 비밀값처럼 보이는 형태만 가리며 모두 찾지는 못합니다(예: 이름에 비밀 단어가 없는 값, 알려진 접두어가 없는 `Authorization: Bearer` 값). AI 답변은 다시 가리지 않습니다.
- **로그인과 키:** Codex의 로그인 여부는 미리 확인하지 않습니다. 앱 전용 홈에 로그인이 없으면 처음 부를 때 오류가 납니다. Gemini는 읽을 수 있는 API 키가 없으면 시작을 막지만, 키의 유효성과 이용 한도는 실제 요청 전에는 확인하지 않습니다.
- **기록:** 두 CLI는 앱 전용 홈에 자체 기록(Codex의 logs·memories 등 SQLite, agy의 대화 DB·로그)을 남깁니다. 질문 내용이 담길 수 있으며, 보관·삭제 정책은 아직 확인하지 않았습니다.
- **agy 앱 전용 홈은 실행 전에만 정리합니다.** 실행 전마다 훅·MCP 설정을 지우고 거부 규칙을 다시 씁니다. 도구 제한과 울타리를 모두 뚫은 실행이 그 홈에 훅이나 MCP 서버를 심으면, 그 폴더로 CLI를 수동 실행하면 울타리 없이 실행될 수 있습니다. 앱은 Gemini의 수동 로그인 명령을 안내하거나 실행하지 않습니다. 실행 뒤 정리와 실패 시 폴더 옮기기는 취소·설치 확인과 겹칠 때 정상 로그인 폴더를 옮길 수 있어 넣지 않았습니다(2026-11-09 사용자 결정).
- **agy 홈 바꾸기는 공식 기능이 아닙니다.** agy 업데이트로 동작이 바뀔 수 있습니다. agy는 작업 폴더의 `.agents/` 설정도 읽으므로 앱은 매번 빈 임시 폴더에서 실행합니다. `sandbox-exec`는 Apple이 사용 중단으로 표시한 도구이고, 사라지면 macOS에서는 AI를 실행하지 않습니다.
- **단독 방식:** 다른 AI가 원본과 대조하지 않습니다. 앱은 응답 형식·근거·자료 변경 여부를 검사합니다. 코드 질문은 관련 파일을 더 읽지 않으므로 선택한 파일 밖의 동작은 확인하지 못합니다. AI 개요와 기획 대조는 고른 AI가 요청한 파일도 읽습니다.

## 실행

macOS arm64 패키지 경로:

`out/Code Learning-darwin-arm64/Code Learning.app`

Windows 설치 프로그램은 Windows에서 `npm run make:win`으로 만듭니다. Squirrel 설치 파일 경로는 `out/make/squirrel.windows/x64/Code-Learning-win-x64-Setup.exe`입니다.

개발 실행은 이 폴더에서 `npm start`입니다. 설치된 의존성 버전은 `package-lock.json`에 고정했습니다. 새 환경에서는 `npm ci` 후 아래 검증을 실행합니다.

tree-sitter 패키지들은 macOS arm64·Windows x64용 N-API 미리 빌드 파일을 포함하므로 설치 스크립트가 필요 없어 `allowScripts`에서 차단하며, `.npmrc`의 `strict-allow-scripts=true`는 검토하지 않은 설치 스크립트가 추가되면 설치를 실패시킵니다.

```sh
npm run typecheck
npm test
npm run package
npm run test:electron
npm run test:packaged
```

macOS에서는 `npm run test:ai-sandbox`로 임시 파일의 쓰기 차단도 검사합니다. CI(`.github/workflows/ci.yml`)는 macOS·Windows에서 타입·단위·Electron·패키지 검사를 실행합니다. Windows에서는 설치 프로그램 생성과 설치·실행·제거 검사도 실행합니다.

macOS에서는 Codex를 개인 설정(`~/.codex`)과 분리된 앱 전용 위치(`~/Library/Application Support/Code Learning/codex-home`)로 실행합니다. 처음 한 번 `CODEX_HOME="$HOME/Library/Application Support/Code Learning/codex-home" codex login`으로 로그인해야 합니다. Antigravity(agy)는 앱 전용 폴더를 `HOME`으로 주어 실행하며(공식 기능 아님), 실행 전마다 `settings.json`의 `modelProvider`를 `gemini`로 고정합니다. Gemini는 Google AI Studio API 키로만 연결하고 기존 Google 로그인 토큰 파일은 읽거나 지우지 않습니다. 키는 Electron `safeStorage`로 암호화해 `<userData>/gemini-api-key.bin`에 권한 `0o600`으로 저장합니다. 암호화를 쓸 수 없으면 저장을 거부합니다. 앱은 키 저장 또는 Gemini 전송 때만 키체인에 접근하며, Apple 서명이 없어 업데이트 후 Gemini를 처음 실행할 때 macOS가 키체인 접근을 물으면 **허용(또는 항상 허용)**을 선택해 주세요. 저장·삭제는 순서대로 처리하며, UI는 변경과 설치 재확인이 끝날 때까지 AI 시작을 막습니다. 키는 agy 실행의 `GEMINI_API_KEY` 환경 변수로만 넘기고, Codex·설치 버전 확인에는 넘기지 않습니다. 키를 IPC 응답·로그·오류 메시지·평문 파일에 넣지 않습니다. `npm run test:agy-live -- -t 'A8 local|A9 local'`은 가짜 키로 로컬 서버만 시험합니다. 실제 계정 시험에는 `GEMINI_API_KEY`와 사용자 승인이 필요합니다.

Windows의 Codex 앱 전용 홈은 `%APPDATA%\Code Learning\codex-home`입니다. 처음 한 번 PowerShell에서 다음 명령으로 로그인합니다.

```powershell
$env:CODEX_HOME = "$env:APPDATA\Code Learning\codex-home"
codex login
```

`npm run test:codex-live`는 사용자 Codex 계정으로 비밀 없는 작은 시험 코드를 실제로 보내는 연결 시험(C01~C03 일부)이라 위 목록과 `npm test`에 포함하지 않습니다. 앱 화면 없이 실행 코드만 시험하며, 결과는 `test-results/codex-live.json`에 통과 여부·분류만 남깁니다.

계정 요청 없이 Codex의 제공 도구와 agents 설정 위치만 확인하려면 `npm run test:codex-live -- -t 'C05 local|C07 local'`을 실행합니다. macOS `sandbox-exec`와 로컬 포트 열기가 필요하며, 임시 HOME·CODEX_HOME과 가짜 응답 서버만 사용합니다. 외부 통신·개인 설정·키체인 경로 접근을 차단하고, 도구 호출 응답은 만들지 않습니다. C05는 가짜 개인 홈의 agents 자료만 읽습니다. C07은 일반 `tools`와 Responses Lite의 `input.additional_tools`, Code Mode의 `exec` 설명에 있는 도구 선언을 수집합니다. 지연 제공되는 도구까지 모두 보인다는 보장은 없으며, 이 결과를 실제 로그인 조건의 C04 통과로 취급하지 않습니다.

로컬 결과는 `test-results/codex-local-probe.json`과 실행별 `codex-local-probe-<ID>.json`에 도구 이름·종류·수치만 기록합니다. 프롬프트·응답·헤더 원문을 저장하지 않으며, 로컬 시험만 실행하면 기존 `codex-live.json`은 보존합니다.

C07은 현재 앱 설정, `code_mode`·`code_mode_only` 끄기, 공식 `model_catalog_json`으로 직접 도구 모드·파일 편집 도구 없음 설정을 지정하는 세 조건을 비교합니다. 뒤의 두 조건은 시험에만 적용합니다. 카탈로그 시험은 공식 0.163.0의 `gpt-6.1-sol` 자료와 같은 CLI 버전만 허용하며, 원본에서 `tool_mode`·`apply_patch_tool_type` 두 필드만 바꿉니다. 시험 자료의 출처·해시는 `tests/fixtures/codex-model-0.163.0.json`, 라이선스·고지는 같은 폴더의 `codex-model-LICENSE.txt`·`codex-model-NOTICE.txt`에 있습니다. 앱은 이미지·협업 끄기와 Code Mode의 `functions` 간접 도구 제외를 적용했지만 `exec` 자체는 남아 있습니다(위 ‘알려진 한계’).

화면 자동검사는 서로의 창 포커스에 영향을 줄 수 있으므로 순서대로 실행합니다. 테스트는 자체 임시 프로젝트와 별도 앱 데이터 경로를 사용하며 외부 AI를 호출하지 않습니다. 작은 탐색 예제는 `fixtures/small-ts`입니다.

## 개발 역할과 화면 연결 기준

**Claude가 기획·결과 검토·커밋을 맡고, Codex가 브리지를 통해 구현·테스트·문서·보안 검토를 맡습니다.**

화면은 시스템의 밝게·어둡게 설정을 따릅니다. 상단에 보기 버튼과 질문 버튼을 두고, 코드 읽기·함수 안 순서에는 파일 목록과 검색을 표시합니다. 질문 버튼으로 오른쪽 질문 패널을 열고 닫습니다. 코드 읽기와 변경 보기는 같은 문법 색을 쓰며, 근거 버튼은 작은 칩으로 표시합니다. 코드 안 찾기(⌘F / Ctrl+F), 코드 글자 크기(12~20px), 줄바꿈을 지원합니다. 1100px 이하에서는 질문 패널을 아래로 쌓습니다.

질문·파일 설명·AI 개요의 체크박스는 ‘보낼 자료에 동의’로 표시합니다. 전체 동의 문장은 바로 아래 **무엇을 보내나요?**를 펼쳐 읽습니다. 처음에는 접혀 있고 체크박스의 접근성 설명에도 전체 문장을 연결합니다. 코드 읽기에서 함수를 고르면 줄 번호 왼쪽에 단계 번호가 표시됩니다. 같은 줄의 여러 단계는 첫 번호에 ‘+’를 붙이고, 누르면 첫 단계의 근거로 이동합니다. 현재 단계는 강조되며 처리 중이거나 코드가 바뀌면 누를 수 없습니다. 키보드로는 단계 목록을 사용합니다. ⌘P 이동 창은 아직 적용하지 않았습니다.

- 화면이 쓰는 API: `src/shared/contracts.ts`의 `LearningApi`와 `window.learning`.
- 화면 상태: `src/renderer/selection.ts`에서 현재 보기(`overview | map | flow | code | changes | function | plan`)와 함수·단계 선택을 공유합니다. `flow`는 기능의 흐름 따라가기, `function`은 함수 안 순서, `plan`은 기획과 비교입니다. 프로젝트가 바뀌면 한눈에 보기로, 파일을 선택하면 코드 읽기로 이동합니다. 함수 안 순서에서 파일을 고르면 그 보기에 머뭅니다.
- `openProject()`는 OS 폴더 선택창을 엽니다. 화면에서 임의 경로를 전달하지 않습니다.
- `readSource()`와 `readEvidence()`는 main이 발급한 프로젝트·파일·근거 ID만 받습니다.
- `cancel()`은 현재 프로젝트를 닫고 작업을 정리합니다. 비동기 응답은 요청 번호를 대조한 뒤 반영합니다.
- `onProjectEvent()` 수신 시 이전 근거 강조를 해제합니다. UI가 파일·DB·셸에 직접 접근해서는 안 됩니다.

변경·실패·취소·AI 미연결 상태를 디자인에도 유지해야 합니다. 디자인 교체를 위해 프로세스 권한이나 분석 로직을 renderer로 옮기지 않습니다.

취소 성공은 `role="status"`·`.notice--info`, 오류는 `role="alert"`로 구분합니다. 취소 문구 ‘작업을 취소했습니다.’는 자동검사에서도 사용합니다. AI 개요는 `src/shared/ai.ts`의 `overviewSchema`(소개·기능 후보·구성 역할·모르는 것, 함수는 이름만)와 `OverviewResult`(읽은 파일·읽기 제한·검토 표시)이고, `startOverview()`로 시작해 `onLearningEvent()`의 `overview-completed`로 받습니다. 프로젝트 전체 실행 흐름 타입은 없습니다. `ProjectView.overview`는 폴더를 열 때 worker가 계산한 소개·시작점 후보입니다. 후보는 근거 ID가 아니며, 화면은 파일을 다시 읽어 해시가 같을 때만 그 함수를 고릅니다. 열린 뒤 변경 이벤트가 오면 개요에 ‘다시 확인 필요’를 표시합니다. 개요는 `ai_overviews`에 저장되고, 다시 열면 읽은 파일의 해시가 모두 같을 때만 근거를 main에 다시 등록합니다. `CodeStep`은 구문 위치이며 실제 실행 흐름을 뜻하지 않습니다. `CodeStep.detail`은 조건·반환 값 같은 원문 일부(최대 300자)이고, `branch`는 if의 조건이 맞을 때와 아닐 때 같은 함수 안에서 이어지는 단계 ID입니다. 문장 목록 밖이라 확인할 수 없으면 null이며, 화면은 ‘다음 연결을 확인하지 못했어요’로 표시합니다. `CodeSymbol.params`는 매개변수 원문입니다.

AI 설명 계약은 `src/shared/ai.ts`의 `Explanation`입니다: `summary`, `steps`(제목·입력·처리·결과·다른 경우·근거 ID), `claims`(코드 근거 또는 일반 개념), `terms`, `examples`, `unknowns`. `examples`는 필수이며 빈 배열도 허용합니다. 최대 3개이고 각 항목에 `given`(가정한 입력), `result`(예상 결과), `evidenceIds`(근거 ID)를 담습니다. `LearningResult`는 원래 질문·근거·`sources`(제공한 파일별 근거와 경로)·`limitations`(읽기 제한)·호출/응답 모델·검토 상태를 함께 전달합니다. 새 결과는 ‘AI 대조 없음’이며, 예전 저장 결과의 ‘AI 검토됨’도 유지합니다. main에서 형식·참조·최신성을 검사합니다. AI 검토는 정확성 보장이 아닙니다.

- `learningModeSchema`는 새 요청의 사용 방식으로 `codex | claude-code | antigravity`만 허용하며 `local-worker`는 거절합니다. 저장 결과의 `mode`는 `resultModeSchema`를 써서 이전의 `local-worker`도 읽습니다(파일 설명·기능 정리·기획 대조). `mode`가 없는 질문·개요의 이전 결과는 `models`의 `reviewing` 기록으로 ‘로컬 워커(이전 방식)’을 표시합니다.
- `checkConnections()`는 설치·버전과 미검증 이유를 반환합니다.
- `startExplanation()`은 허용된 프로젝트·근거 ID, 기대 해시, 질문, 사용 방식 `mode`, 명시적 전송 동의를 필수로 받습니다. 이어 묻기의 `conversationId`는 선택 항목입니다. Codex 단독·Gemini 단독은 이번 실행의 설치 확인에서 해당 실행기를 찾은 뒤에만 시작하고, Claude Code 단독은 실행 준비 차단 오류를 반환합니다. Windows에서는 Codex 단독만 시작할 수 있습니다.
- `onLearningEvent()`는 작업 ID에 연결된 진행·완료·실패 이벤트를 받습니다.
- `cancelExplanation({jobId})`는 해당 AI 작업만 취소합니다. 기존 `cancel()`은 프로젝트까지 닫습니다.
- `src/renderer/ai-panel.tsx`에는 질문 패널의 기능 연결을 추가했습니다.
- 진행 단계 `reading-related`는 AI 개요·기획 대조에서 고른 파일 읽기이며, 코드 질문에는 없습니다. 코드 질문은 `collecting`(자료 확인) → `explaining`(설명) → `validating`(검증) 순서입니다. 질문 기준 경로·행, 선택한 코드와 그 파일의 전송 동의, 답변의 파일별 근거 버튼과 단계·코드 설명별 근거 버튼(`SourceButtons`)을 유지해야 합니다. 답변 근거를 보러 이동하는 것과 새 질문 대상을 선택하는 것은 구분합니다.
