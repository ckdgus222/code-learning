# R3: 출시 전 보안 점검 (2026-11-13)

## 범위와 완료 기준

`v1.0.2` 이후 변경 중 패키징, Markdown 내보내기의 파일 쓰기, 외부 프로젝트 입력을 읽는 분석기의 한도를 점검한다. 로컬 테스트 캐시가 배포물에 들어가는 문제를 고치고 검토 결과를 기록하는 한 단계이며, 커밋 하나로 마친다. 새 의존성·공개 API·분석 정책은 추가하지 않는다. 푸시·태그·출시는 별도 단계다.

완료 기준:

- `node_modules/.vitest-cache`와 `node_modules/.vite` 및 그 하위 파일이 로컬 패키징 결과에서 빠진다. 중첩된 `node_modules`에서도 같은 캐시 경계를 적용한다.
- 앱 실행에 필요한 루트 `.vite`, 일반 의존성, 캐시와 이름만 비슷한 경로는 기존 허용 규칙을 따른다.
- 캐시 제외를 제거하면 실패하는 회귀 검사를 두고, 실제 로컬 캐시가 있는 상태로 만든 macOS 앱의 ASAR와 풀린 리소스를 확인한다.
- 보안 검토의 발견은 재현 근거, 기존에 기록된 한계, 미검증 항목을 나눠 기록한다. 정책·구조 변경이 필요한 발견은 구현을 확대하기 전에 사용자에게 알린다.

## 입력과 출력

- `forge.config.ts`의 기존 `packagerConfig.ignore(file: string): boolean`을 유지한다. `true`는 제외, `false`는 포함이다.
- 설치된 Electron Packager의 경로 정규화 규약을 확인하고 그 규약에 맞춰 경로의 디렉터리 경계를 판별한다. 루트 빈 경로도 기존대로 포함한다.
- 내보내기 `saveExport(projectRoot, file, text, stopped): Promise<string>`와 IPC 계약은 검토 대상이며 이번 기획에서 변경하지 않는다.

## 경계와 충돌

1. 루트 `.vite`를 캐시와 혼동하면 앱이 시작하지 않는다. `node_modules` 아래의 캐시 디렉터리만 제외한다.
2. `.vite-extra`나 `.vitest-cache-extra` 같은 정상 이름을 잘못 제외하지 않도록 전체 디렉터리 이름과 경계를 검사한다.
3. 중첩된 의존성 캐시를 놓치지 않도록 모든 `node_modules` 경계를 검사하고 회귀 테스트에 넣는다.
4. Windows와 macOS의 구분자 차이는 Packager가 전달하는 경로 규약을 기준으로 처리한다. 실제 Windows 배포물 검사는 출시 빌드 후 남는 항목으로 구분한다.
5. 패키징 중 캐시가 추가되어도 같은 제외 규칙이 적용되어야 한다. 화면 검사는 순차 실행하고, 기존 `out/` 앱 프로세스는 종료하지 않는다.

## 작업 분담과 순서

1. planner가 이 계획의 범위·누락·완료 기준을 읽기 전용으로 검토한다.
2. security가 `src/main/export-file.ts`와 호출부·스키마, `v1.0.2` 이후 분석기 변경과 입력·출력·취소 한도를 읽기 전용으로 검토한다. 메인은 패키징 규약과 실제 배포물을 확인한다.
3. 메인이 제외 설정을 수정하고 tester가 `tests/build-hardening.test.ts`에 회귀 검사를 추가한다. 같은 파일을 동시에 수정하지 않는다.
4. 최종 변경 검토, 아래 검증, 결과 문서 반영 후 로컬 커밋한다.

## 검증

- 변경 전 새 캐시 회귀 검사가 실패하고, 제외 설정을 적용한 뒤 통과하는지 확인한다. 기존 테스트의 기대값은 바꾸지 않는다.
- `npm run typecheck`, `npm test`, `npm run package`, `npm run test:electron`, `npm run test:packaged`를 실행한다. 화면 검사 전에 남은 프로젝트 Electron 프로세스를 확인한다. 패키지 검사는 앱 창이 잠깐 보인다고 미리 알린다.
- 실제 ASAR 및 `app.asar.unpacked`에 캐시 디렉터리가 없는지 확인하고, 앱 리소스에서 로컬 홈·작업 폴더 경로의 포함 여부를 검사한다. 계정 경로나 캐시 내용은 문서·로그에 옮기지 않고 결과만 기록한다.
- `git diff --check`, 변경 내용·비공개 문서 제외 여부를 확인한다. 최종 상태에서 통과한 검사는 관련 변경이나 새 실패가 없으면 다시 실행하지 않는다.
- 실제 AI 요청, 실제 API 키, 실제 저장 창·클립보드는 사용하지 않는다. 로컬 macOS 결과를 Windows 실제 검증으로 표시하지 않는다.

## 검토 기록

- 기획 검토: 필수 보완 없음. 새 캐시 검사의 변경 전 실패를 먼저 확인한 뒤 설정을 수정했다.
- 저장·분석 보안 검토: 지정 범위에서 새로 조치할 취약점은 발견하지 못했다. 저장 폴더 바꿔치기, 큰 입력의 작업 스레드 자원 사용, 동적 Python 주소와 읽지 못한 경쟁 주소는 기존에 기록된 한계로 분리했다. 추가 퍼징·의존성 취약점 조사는 이 단계 범위에 포함하지 않는다.
- 최종 코드 검토: 캐시 경계·필수 파일 보존·기존 검사 유지에 추가 지적 없음. 설치된 Packager는 Windows 구분자를 `/`로 바꿔 전달하고 Vite 플러그인은 사용자 `ignore` 함수를 유지한다.
- 실제 검사 결과는 [구현 상태](implementation-status.md)에 기록한다.
